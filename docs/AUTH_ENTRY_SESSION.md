# 회원가입 진입과 세션 복원 수정

첫 방문에도 예시 계정을 로그인된 상태로 만들고 홈을 바로 렌더링하던 문제를 고쳤습니다. 이제 세션이 없으면 `/signup`에서 시작합니다. 로그인 링크로 `/login`을 열 수 있고, 로그인 화면에서도 회원가입으로 돌아갈 수 있습니다.

업무, 홈, 내역과 계정 화면은 RequireAccount 안에서만 렌더링합니다. API 모드에서는 보호 화면을 열기 전에 세션 조회를 마칩니다. 확인 중에는 로딩을, 서버 오류에는 다시 시도를 표시합니다. 401이면 회원가입으로 보내며 요청했던 내부 경로와 검색 조건을 로그인 후 복귀 경로로 남깁니다. 로그인 전에는 해당 화면의 자료 API를 호출하지 않습니다. 만료와 로그아웃 뒤에는 로그인 화면으로 보내며, 뒤로 가기로 홈에 들어갈 수 없습니다.

## 예시 세션과 실제 세션

- 데모는 sessionStorage의 `workbridge.demo.session.v1`에 표시용 ID, 이름, 이메일, 만료 시각만 보관합니다. 8시간 후 만료되고 비밀번호와 인증 토큰은 저장하지 않습니다. 이는 실제 서버 인증이 아닙니다.
- 같은 탭을 새로고침하면 예시 세션과 프로필을 복원합니다. 업무 기록은 기존 메모리 예시라 새로고침 후 비워집니다. 다른 사람의 기본 예시 기록을 새 계정에 붙이지 않습니다.
- API 모드는 브라우저 저장소의 예시 계정을 무시하고, 설정한 GET 세션 경로에 쿠키를 포함해 요청합니다. 성공 응답의 user를 확인해야 내부 화면을 엽니다. 저장소만 조작해서 실제 계정으로 인증할 수 없습니다. 서버는 모든 자료 요청의 권한도 별도로 검사해야 합니다.
- 만료는 서버의 401 응답을 따릅니다. 예시 모드는 타이머와 탭 복귀 시각도 확인합니다. 로그아웃이 실패하면 기존 세션을 유지하며, 늦은 세션 조회 응답이 로그아웃을 되돌리지 않도록 막습니다.

## 계정 서버 미연결 메시지

프론트엔드의 VITE_AUTH_SIGNUP_PATH, VITE_AUTH_LOGIN_PATH, VITE_AUTH_SESSION_PATH가 비어 있으면 실제 가입과 로그인은 쓸 수 없습니다. API 모드는 이 조건을 화면에 미리 안내합니다. 요청을 성공으로 꾸미거나 임의의 인증 URL을 만들어 보내지 않습니다.

2026-11-21에 노션 API 작업 트래커의 작업 이름과 API 경로에서 로그인, 계정, 인증, auth, session을 조회했지만 항목이 없었습니다. 배포 서버 `https://gdgoc2026a.up.railway.app/openapi.json`도 확인했으며 공개된 경로는 `/health`, `/health/db` 두 개뿐이었습니다. 따라서 프론트엔드 진입 문제를 고치는 것만으로 실제 회원가입 서버가 생기지는 않습니다.

백엔드에서 아래 규격을 확정하고 구현한 뒤 환경 변수를 채워야 합니다. 서버 세션의 쿠키, 만료와 폐기, CORS와 요청 권한도 백엔드 담당 범위입니다. VITE 변수는 공개 설정이므로 비밀 키를 넣지 않습니다.

| 연결      | 프론트엔드가 현재 기다리는 형식                                                                  |
| --------- | ------------------------------------------------------------------------------------------------ |
| 회원가입  | POST `{ name, email, password }`, 성공 `{ user: { id, name, email } }` 또는 verificationRequired |
| 로그인    | POST `{ email, password }`, 성공 `{ user }`와 서버 세션 쿠키                                     |
| 세션 확인 | GET, 유효하면 `{ user }`, 미인증이면 401                                                         |
| 로그아웃  | POST, 성공 후 세션 쿠키 폐기                                                                     |

이 표는 기존 어댑터의 연결 제안이며 확정된 서버 계약이 아닙니다. 실제 경로는 백엔드 구현에 맞춰 `.env.local` 등에 설정하고 Vite를 다시 시작해야 합니다. 계정 서버를 연결하지 않은 상태에서는 기본 demo 모드로 회원가입부터 이어지는 화면 흐름을 확인할 수 있습니다. 실제 소셜 로그인과 인증 이메일 발송은 서버 연결 후 별도 확인이 필요합니다.

## 검증

기존 작업 공간 회귀 검사는 테스트 fixture로 로그인 상태를 명시합니다. 실제 앱에 우회 플래그를 넣지 않았습니다. 별도 세션 검사는 이 fixture 없이 첫 진입, 보호 경로, 새로고침 복원, 잘못된 세션, 로그아웃과 서버 오류를 확인합니다. 서버 모의 응답은 실제 인증 성공을 뜻하지 않습니다.

검증 상태: 사용자 터미널에서 lint, build, 모델 검사 15개와 UI 검사 69개가 통과했습니다. 이슈 https://github.com/GDGoC-2026TeamA/Frontend/issues/27, 브랜치 `fix/#27`. 실제 서버 통합 QA는 실행하지 않았으며 성공을 주장하지 않습니다.
