# 2차 구현과 확인 상태

기준: Figma `112:553`의 02~07 화면, 2026-11-20.

## 추가한 화면

홈에서 새 업무 등록을 누르거나 `/work/new`로 들어가면 홈 위에 팝업이 열립니다. 단계마다 왼쪽 위에 ‘새 업무 등록’ 제목이 있습니다.

- 업무 이름과 설명, 기존 업무 자료와 새 시스템 매뉴얼 선택
- 예시 자료 채우기와 삭제, 형식과 크기 검사
- 취소할 수 있는 예시 분석
- 기존 방식과 새 방식 비교, 예시 근거 자료
- 미확인 항목의 절차와 질문 수정
- 수정 반영 후에도 현장 확인 질문 유지

실제 선택한 파일로 예시 분석 결과를 만들지 않습니다. 파일은 서버로 전송하지 않으며, 분석 연결 전 안내를 표시합니다. 명시적으로 선택한 피그마 예시만 비교 결과로 표시합니다. 수정은 React 메모리에만 남으며 창을 닫거나 새로고침하면 사라집니다. 새 방식 익히기 버튼은 3차 범위 안내를 표시합니다.

## 이번 환경에서 확인한 결과

- `npm run lint`: 통과.
- `npm run build`: 통과.
- `npm run dev -- --port 5180 --strictPort`: Vite ready와 로컬 주소 출력 확인.
- 브라우저 동작 검증: 완료하지 못함. 5173 접속은 시간 초과였고, 5180 브라우저 접근은 승인 게이트에서 거절됐습니다. 화면 캡처와 E2E 통과를 확인한 상태가 아닙니다.
- GitHub 업로드: 완료하지 못함. 연결된 GitHub 앱의 이슈와 브랜치 생성이 HTTP 403 `Resource not accessible by integration`을 반환했습니다. 로컬 Git fetch도 네트워크 오류로 실패했습니다.

## 다음 환경에서 실행할 검사

```bash
npm ci
npm run lint
npm run build
npm run test:e2e
npm run dev
```

추가한 `tests/registration.spec.js`는 누락 입력, 실제 파일 오인 분석 방지, 수정 문구 반영, 미확인 상태 유지, 분석 취소, 키보드와 모바일 배치 및 접근성을 검사합니다. 해당 테스트가 통과했다고 간주하면 안 됩니다. 브라우저 검증이 가능해지면 전체 검사를 실행하고 캡처를 확인해야 합니다.

GitHub 쓰기 연결이 복구되면 최신 main 변경을 확인하고, 구현 이슈 번호에 맞춘 브랜치에 목적별 커밋을 올린 뒤 PR을 만들어야 합니다. main 병합은 팀 리뷰 후에 합니다.
