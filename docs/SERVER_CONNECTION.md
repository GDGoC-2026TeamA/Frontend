# 서버 연결 상태

2026-11-21 한국 시간 기준입니다.

## 실행 설정

`.env.example`에는 아래 한 줄만 둡니다. 파일을 복사하지 않아도 같은 주소가 기본값입니다.

```dotenv
VITE_API_BASE_URL=https://gdgoc2026a.up.railway.app/api/v1
```

`src/services/config.js`에서 API 주소와 기본 데이터 모드를 관리합니다. 홈, 목록, 학습, 업무 처리와 계정이 같은 모드를 씁니다. 기본값은 `api`입니다. 로그인한 예시 계정을 자동으로 만들지 않으며 서버 조회 실패를 예시 데이터로 바꾸지 않습니다.

이전에 만든 `.env.local` 또는 배포 환경에 `VITE_DATA_MODE=demo`가 있으면 삭제해야 합니다. Vite 환경 변수는 실행 중인 개발 서버를 재시작하거나 배포 코드를 다시 빌드해야 반영됩니다. `.env.example` 자체는 Vite가 읽는 설정 파일이 아닙니다.

디자인 검토용 예시가 필요할 때만 `VITE_DATA_MODE=demo`를 별도로 설정하세요. Playwright의 기본 UI 검사는 이 값을 명시적으로 설정합니다. API 검사는 모의 서버 응답을 쓰며 운영 서버의 성공을 뜻하지 않습니다.

## 실제 배포 서버 확인

- `https://gdgoc2026a.up.railway.app/openapi.json`의 경로는 `/health`, `/health/db` 두 개입니다.
- `https://gdgoc2026a.up.railway.app/api/v1/home` 응답은 `{"detail":"Not Found"}`입니다.
- 백엔드 main의 `main.py`에도 두 상태 확인 경로만 있습니다.

현재 서버에는 계정과 업무 API가 없습니다. 주소 정리만으로 회원가입, 로그인이나 업무 저장을 완료할 수 없습니다. 프론트의 업무 요청 경로는 기존 API 트래커 기준이며 백엔드 구현이 필요합니다.

## 계정 연결에 남은 작업

빈 `VITE_AUTH_*` 항목은 `.env.example`에서 삭제했습니다. 소셜 로그인, 세션, 비밀번호 재설정 등의 경로를 추측해서 넣지 않았습니다. 기존 계정 어댑터는 보관하며, 백엔드 API가 생기면 [계정 연결 규격](FINAL_FRONTEND.md)의 선택 설정으로 연결할 수 있습니다. 설정하지 않은 계정 요청은 서버 미연결 안내를 표시합니다. 잘못된 기본값으로 프론트 주소에 비밀번호를 보내지 않습니다.

백엔드 팀은 계정 API 경로, HTTP 메서드, 응답, 인증 방식과 허용 프론트 주소를 확정해야 합니다. 현재 계정 어댑터는 세션 쿠키와 `{ user: { id, name, email } }` 응답을 예상합니다. 서버의 인증 방식이 다르면 어댑터도 수정해야 합니다. 쿠키 방식이면 CORS에 실제 프론트 주소와 credentials 허용이 필요합니다.

컴포넌트 미리보기는 기존처럼 개발 환경에서만 기본으로 열립니다. 배포에 별도로 넣어야 할 때만 `VITE_ENABLE_COMPONENT_PREVIEW=true`를 설정하세요.

## 수정본 검사

- 모델 검사 9개, ESLint와 프로덕션 빌드가 통과했습니다.
- 기본 API 모드와 미설정 로그인에서 비밀번호를 전송하지 않는지 확인하는 Playwright 검사를 추가했습니다.
- 이 실행 환경은 로컬 서버 접속도 차단합니다. Playwright 실행을 시도했으나 `127.0.0.1` 접속이 `EACCES`로 실패해 브라우저 검사 결과는 확인하지 못했습니다.
- 배포 서버의 API 명세와 `/api/v1/home` 응답은 브라우저에서 직접 확인했습니다. 실제 계정 생성, 데이터 업로드와 저장은 하지 않았습니다.
