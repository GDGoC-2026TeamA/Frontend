## 예시 학습의 기준

- 공유받은 업무는 공개된 비교 자료와 절차를 읽습니다. 학습 시작 시 복사해 이후 업무 수정과 분리합니다. 개인 업무는 저장한 개인 기준을 읽습니다.
- 연습 답안과 AI 대화는 탭 메모리에만 남습니다. 업무의 공개 자료에 쓰지 않으며 새로고침하면 초기화됩니다. 로그인이나 서버의 접근 권한을 구현했다는 뜻은 아닙니다.
- 추천은 수량 불일치 항목입니다. 이 항목만 고르면 1문제, 품목 검색과 입력 항목만 고르면 2문제, 둘 다 고르면 3문제입니다. 항목 선택 전에는 연습을 시작할 수 없습니다.
- 품목 코드 검색, 실제 수량 입력, 전표 대조 순서를 확인합니다. 복수 선택 문제는 필요한 두 항목을 모두 고르고 오답 항목을 고르지 않아야 정답입니다.
- 전표 20개, 실제 18개라면 실제 18개를 입력하고 차이 사유를 남깁니다. 승인 담당자는 예시 매뉴얼에 없으므로 정답에서 제외합니다.
- 결과는 실제 답안으로 계산합니다. 다시 연습하면 이전 답안과 점수를 지웁니다. 문제 사이를 오갈 때는 답안과 이유를 유지합니다.
- 확인된 예시 자료와 일치하는 기준에서만 예시 문제를 만듭니다. 사용자가 수정한 예외 절차를 검증된 사실로 채점하지 않습니다. 기준 자료가 없는 다른 업무에 재고 예시를 섞지 않습니다.
- 예시 AI 답변은 지정한 질문에 맞춘 예시입니다. 실제 AI를 호출하지 않습니다. 그 밖의 질문은 근거 없는 답을 만들지 않고 확인 필요로 남깁니다.
- 학습 결과의 ‘업무 처리하기’는 기존 `/work/input`으로 연결합니다. 4차 실제 업무 화면은 이번 변경에 포함하지 않습니다.

## 서버 연결 범위

`VITE_DATA_MODE=api`에서는 `GET /tasks/:id`의 실제 업무와 자료를 읽고 `POST /tasks/:id/questions`에 `{ question }`을 보냅니다. 응답의 `answer`, `sources: [{ materialId, page }]`, `needsReview`를 확인합니다. 자료 이름은 해당 업무의 `materials`와 연결합니다. 질문 실패와 취소 시 입력은 남기고 늦게 도착한 취소 응답은 버립니다. 실패를 예시 답변으로 바꾸지 않습니다.

현재 문서화된 질문 응답에는 인용 원문이 없습니다. 자료와 위치만 표시하고 원문이 없다는 안내를 씁니다. 파일 이름, 페이지나 원문 구절을 만들어 채우지 않습니다. 서버가 범위나 버전을 보내지 않으면 확인되지 않았다고 표시합니다.

문서화된 연습 답안 요청은 단일 `optionId`만 받으며, 새 복수 선택 문항의 정답과 근거 계약은 정해지지 않았습니다. API 모드의 연습 생성과 채점은 미연결 안내로 남겨 두었습니다. 서버 자료에 예시 문제와 정답을 붙이지 않습니다. 실제 서버에서 AI 답변이 성공하는지와 인증, 기록 저장, 버전 고정은 백엔드 연결 확인이 필요합니다.
