# 백엔드 연결 제안

아래 함수명과 데이터 형식은 협의를 위한 제안입니다. 확정된 API 계약이나 구현된 서버가 아닙니다. 실제 엔드포인트, 인증, 파일 형식, 작업 상태와 오류 코드는 백엔드 담당자와 정해야 합니다.

## 현재 연결 경계

`ComponentPreviewPage` → `foundationService.getFoundationPreview()` → `services/demo/foundation.js` → `data/foundation.js`

실제 HTTP 요청은 없습니다. `services/api/client.js`는 JSON 전송과 실패 상태를 공통으로 처리할 준비만 했습니다. 아직 업무별 실제 함수를 만들지 않았습니다. 파일 전송은 나중에 FormData 전용 경로를 추가해야 하며 현재 JSON client에 File 객체를 넘기면 안 됩니다.

## 필요한 함수의 제안안

| 함수명               | 요청의 핵심                                     | 응답의 핵심                                | 추가 차수 |
| -------------------- | ----------------------------------------------- | ------------------------------------------ | --------- |
| `analyzeMaterials()` | 업무명, 서버에 업로드된 기존 양식과 매뉴얼의 ID | 업무 ID, 분석 상태, 비교 항목, 미확인 항목 | 2차       |
| `updateComparison()` | 업무 ID, 비교 항목 수정값과 사용자 확인 상태    | 저장된 비교 항목과 확인 상태               | 2차       |
| `getPractice()`      | 업무 ID, 연습 상황 ID                           | 질문, 상황, 참고 가능한 자료 ID            | 3차       |
| `submitPractice()`   | 연습 ID, 사용자 응답                            | 피드백과 관련 자료 근거                    | 3차       |
| `askQuestion()`      | 업무 ID, 질문, 대화 ID                          | 답변, 근거 목록, 미확인 안내               | 3차       |
| `saveWorkCard()`     | 업무 ID, 카드 제목, 처리 절차와 근거 ID         | 저장된 개인 업무 카드                      | 3차와 4차 |
| `getWorkCards()`     | 업무 ID나 검색 조건                             | 개인 업무 카드 목록                        | 4차       |
| `createWorkDraft()`  | 업무 ID, 오늘 작업 자료의 ID                    | 작업 ID, 초안 항목과 확인 필요 항목        | 4차       |
| `saveWorkResult()`   | 작업 ID, 사용자가 수정한 결과와 확인 상태       | 서비스 내부 작업 결과 ID                   | 4차       |
| `getWorkHistory()`   | 업무 ID나 조회 조건                             | 서비스 내부 작업 내역 목록                 | 4차       |

자료 업로드, 업무 목록과 상세 조회 API도 별도 협의가 필요합니다. 위 이름에 맞추려고 서버 구조를 미리 확정하지 마세요.

## 근거 데이터 예시

```js
// 제안안: 실제 응답 형식 아님
{
  id: 'source-evidence-id',
  materialId: 'uploaded-manual-id',
  source: '새 재고 시스템 매뉴얼',
  location: '3장. 입고 등록 / 12쪽',
  quote: '품목 코드를 확인한 뒤 입고 수량을 입력합니다.',
  verifiedByUser: false
}
```

근거가 없으면 빈 인용문을 채워 넣지 말고 근거 목록을 비우고 미확인 문구를 보내는 구조가 필요합니다. 페이지와 절 위치를 못 찾았다면 위치 정보도 확인되지 않았다고 표시해야 합니다. `verifiedByUser`는 사용자 확인 상태이며 AI 정확도 점수가 아닙니다.

## 실제 연결 시 확인할 내용

- 업무 기준 자료와 이번 작업 자료를 다른 ID와 용도로 구분합니다.
- 이미 등록된 업무를 처리할 때 기준 자료를 다시 업로드하지 않습니다.
- 연습 중 저장한 개인 업무 카드와 이번에 검토한 작업 결과를 따로 저장합니다.
- 분석이 비동기라면 작업 ID와 진행 상태, 실패, 재시도 방식을 먼저 정합니다.
- 사용자가 수정한 값과 AI가 처음 만든 값을 어떻게 남길지 정합니다.
- 요청 취소에는 AbortSignal을 전달하고 오류와 자료 부족을 구분합니다.
- 브라우저에 API 비밀 키를 넣지 않습니다. 인증과 업로드 검증은 서버에서 처리합니다.
- 서비스 내부 저장 성공을 외부 재고 등록이나 예약 확정으로 표현하지 않습니다.

실제 서버가 연결되면 고정 예시를 실제 분석 결과로 표시하지 않도록 응답 출처를 구분하세요. 연결 실패 시 예시 모드로 조용히 전환하지 말고 오류를 보여 주세요.
