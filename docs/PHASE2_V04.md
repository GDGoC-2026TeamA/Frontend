## 연결 범위

- 기본 demo 모드는 명시적으로 선택한 예시 자료만 분석합니다. 실제 파일을 선택하면 서버에 전송하지 않고 문서 분석 미연결 안내를 띄웁니다.
- 예시 업무 저장과 공유는 브라우저 탭의 메모리에서만 바뀝니다. 새로고침하면 초기화됩니다. 서버 저장, 계정 간 실제 공유나 접근 제어 검증을 뜻하지 않습니다.
- 공유받은 자료를 표시하는 데이터는 검토된 절차/질문, 버전과 근거 연결만 복사합니다. 개인 작업 자료, 결과, AI 대화, 개인 카드를 함께 전달하지 않습니다. 승인 담당자처럼 자료에서 확인되지 않은 항목은 계속 확인 필요입니다.
- API 모드에서는 기존 home/jobs/cards 조회를 유지합니다. 조회 실패를 빈 목록이나 예시로 바꾸지 않습니다. 서버의 등록/분석/공유 계약이 확정되지 않아 해당 쓰기 작업은 비활성 또는 미연결 안내입니다.
- 계정 메뉴의 열기/닫기를 연결했습니다. 프로필/설정/로그아웃의 실제 계정 처리는 별도 계정 섹션 범위이며 현재는 미연결 안내를 보여줍니다. 학습과 연습은 3차, 실제 작업/카드는 4차 화면에서 연결합니다.

## 검사와 로컬 실행

검증 상태: 에이전트 환경에서 lint와 build를 통과했습니다. 로컬 서버 접근 제한 때문에 브라우저 검사는 완료하지 못했습니다. 사용자 터미널에서 UI 검사 결과를 확인한 뒤 갱신합니다.

```powershell
npm.cmd run dev
# / : 홈, /tasks : 업무 목록, /work/new : 등록 팝업
npx.cmd playwright test tests/api-client.spec.js tests/foundation.spec.js tests/home.spec.js tests/home-api.spec.js tests/registration.spec.js tests/status-screens.spec.js tests/foundation-v04.spec.js tests/phase2-v04.spec.js
```

UI 검사는 기존 29개와 추가 5개, 총 34개입니다. 변경된 홈 배치/메뉴 수/가이드 이름과 필수 자료 전 분석 비활성 기준으로 기존 검사를 갱신합니다. 새 검사는 소유 범위 필터, 공유 읽기 전용, 개인 저장과 재열기, 공유 확인 취소와 v1/v2 분리, 반응형/접근성을 확인합니다.

팀원이 추가한 `tests/workbridge-qa.spec.js` 서버 통합 QA는 원본을 유지하며 위 UI 검사와 별도로 실행해야 합니다. 로그인/API와 별도 계정, samples 자료, 다른 경로가 필요합니다. 이 작업에서는 서버 통합 QA 통과를 주장하지 않습니다.
