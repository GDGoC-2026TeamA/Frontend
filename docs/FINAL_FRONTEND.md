## 예시 모드와 서버 연결 범위

기본 `VITE_DATA_MODE=demo`는 실제 계정 생성이나 인증이 아닌 예시입니다. 첫 진입에는 회원가입을 표시합니다. 비밀번호는 저장하거나 서버로 보내지 않습니다. 예시 사용자의 ID, 이름, 이메일과 만료 시각만 sessionStorage에 최대 8시간 보관합니다. 같은 탭에서 새로고침하면 예시 로그인 상태와 프로필을 복원하며, 작업 기록은 메모리 예시이므로 초기화합니다. 가입 또는 로그인 예시는 빈 작업 공간으로 시작합니다. 로그아웃과 만료 시 예시 세션, 업무와 작업, 개인 카드와 학습 기록을 비웁니다. API 모드에서는 예시 세션을 인증 근거로 쓰지 않고 서버 세션을 확인합니다. 자세한 진입과 연결 범위는 [AUTH_ENTRY_SESSION.md](AUTH_ENTRY_SESSION.md)를 확인하세요.

카카오와 Google 버튼은 가짜 제공자 로그인 폼을 열지 않습니다. 서버 인증 시작 URL이 설정된 경우에만 그 주소로 이동합니다. 미연결 시에는 다른 로그인 방법을 고르는 안내를 보이며, 데모에서 별도 ‘첫 사용 예시 보기’ 버튼으로 빈 홈을 확인할 수 있습니다. 제공자 인증 성공을 꾸며서 표시하지 않습니다. 콜백 URL의 success, user, token 값은 인증 근거로 쓰지 않습니다.

API 트래커에는 현재 인증, 프로필, 이메일 변경, 업무 수정, 삭제와 공유 계약이 없습니다. 아래 계정 어댑터는 **팀 합의가 필요한 연결 규격 제안**입니다. 확정된 API 구현으로 보지 않습니다. 기본 경로를 추측해 서버로 요청하지 않습니다. `.env.example`의 빈 값을 팀에서 정한 경로로 채워야 합니다. 업무 관리 서버 요청은 계약이 없으므로 저장을 막고 안내합니다. 기존 트래커의 작업, 분석, 학습과 카드 요청 형식은 그대로 씁니다.

| 환경 변수                                             | 어댑터 요청과 필요한 응답                                                         |
| ----------------------------------------------------- | --------------------------------------------------------------------------------- |
| VITE_AUTH_LOGIN_PATH                                  | POST `{ email, password }`, 성공 `{ user: { id, name, email } }`                  |
| VITE_AUTH_SIGNUP_PATH                                 | POST `{ name, email, password }`, 성공 user 또는 `{ verificationRequired: true }` |
| VITE_AUTH_SESSION_PATH                                | GET, 서버가 확인한 `{ user }`, 선택 firstVisit                                    |
| VITE_AUTH_PROFILE_PATH                                | PATCH `{ name }`, 저장이 확인된 `{ user }`                                        |
| VITE_AUTH_EMAIL_PATH                                  | PATCH `{ email }`, 변경이 확인된 `{ user }`, 인증 대기 절차는 추가 합의 필요      |
| VITE_AUTH_LOGOUT_PATH                                 | POST, 본문 없음, 성공 204 또는 JSON                                               |
| VITE_AUTH_RESET_REQUEST_PATH                          | POST `{ email }`, 성공 204 또는 JSON, 주소 존재 여부를 드러내지 않는 안내         |
| VITE_AUTH_RESET_PASSWORD_PATH                         | POST `{ token, password }`, 성공 204 또는 JSON                                    |
| VITE_AUTH_KAKAO_START_URL, VITE_AUTH_GOOGLE_START_URL | HTTPS 서버 OAuth 시작 주소, 로컬 개발에서만 localhost HTTP 허용                   |

계정 경로는 VITE_API_BASE_URL 기준 상대 경로 또는 같은 서버의 절대 경로입니다. 서버 세션 쿠키를 위해 credentials: include를 쓰며, 기존 업무 API는 세션 경로를 설정한 경우에만 이 옵션을 추가합니다. 쿠키, CORS, OAuth state 확인과 코드 교환, 인증 이메일 발송은 백엔드 담당 범위입니다. VITE 변수에 비밀 키를 넣지 않습니다. 재설정 링크의 토큰은 변경 요청에만 쓰고 성공하면 로그인 경로로 바꿉니다. 프론트엔드의 가입 검증은 이름, 이메일 형식, 비밀번호 8자와 확인 일치이며 최종 정책은 서버와 합의해야 합니다.

소유자 메뉴는 scope: owned인 업무에만 열립니다. 실제 저장 권한은 서버에서도 검사해야 합니다. 예시 저장소는 받은 업무 ID를 owned로 바꿔 호출해도 수정과 삭제를 거절합니다. 업무 이름을 바꿔도 이미 검토한 기준과 개인 기록의 복사본은 바꾸지 않습니다. 공유 설정 버튼만으로 미검토 자료를 게시하지 않습니다.

업무 메뉴는 Figma처럼 소유자의 네 항목과 받은 사람의 업무 정보 보기 한 항목으로 나눴습니다. 기존 비교 확인과 새 버전 검토 동작은 ‘자료 교체와 비교 내용 재검토’로 모았습니다. 계정 조회 중에는 로딩을 표시하고, 조회 실패는 다시 시도할 수 있습니다.

## 검사와 로컬 실행

검증 상태: 사용자 터미널에서 lint, build, 모델 검사 9개와 UI 검사 63개가 통과했습니다. 이슈 https://github.com/GDGoC-2026TeamA/Frontend/issues/25, 브랜치 `feat/#25`. 실제 서버 통합 QA는 실행하지 않았으며 성공을 주장하지 않습니다.

```powershell
npm.cmd run dev
```

터미널에 나온 Local 주소를 엽니다. 기본 홈 외에 `/login`, `/signup`, `/profile`, `/settings`를 직접 열 수 있습니다. 서버 연결 전 예시 비밀번호만 입력합니다.

새 브라우저 검사는 계정 입력 검증, 첫 업무 안내, 수정 취소, 소유권과 삭제, 공유 검토 연결, 계정 저장과 로그아웃 실패, 세션 만료와 403, 콜백, 재설정 요청, 모바일과 접근성을 확인합니다. 계정 API 검사는 설정된 테스트 경로의 모의 응답을 쓰며 실제 카카오, Google, 이메일 또는 운영 서버의 성공을 뜻하지 않습니다. 기존 UI 50개와 모델 6개도 함께 확인합니다. 팀의 workbridge-qa.spec.js 통합 QA는 수정하지 않았으며 이번 검사와 별도입니다.
