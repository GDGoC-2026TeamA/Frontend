# WORK BRIDGE

기존 업무 자료와 새 시스템 매뉴얼을 비교해 바뀐 절차를 배우고, 오늘의 작업 자료를 검토하는 웹 서비스입니다. 재고 입고 기록이 대표 시나리오이며 예약 접수는 같은 구조의 확장 예시입니다.

현재 버전은 **1차 공통 UI와 피그마의 ‘1차 / 공통 레이아웃과 홈’ 섹션 4개 화면**입니다. 홈 대시보드, 위치 안내 온보딩, 홈 검색 추천어와 검색 결과를 구현했습니다. 2차 업무 등록과 자료 비교 팝업 6개 화면을 추가했습니다. 예시 분석과 비교 항목 수정까지 연결했으며 실제 서버 등록과 분석은 아직 연결하지 않았습니다.

## 설치와 실행

Node.js 24 이상과 npm이 필요합니다. 이 프로젝트는 JavaScript, JSX와 CSS를 씁니다.

```bash
npm ci
npm run dev
```

터미널에 표시되는 주소를 여세요. 기본 주소는 `http://127.0.0.1:5173`입니다. 포트가 사용 중이면 Vite가 다른 포트를 안내합니다.

개발용 컴포넌트 화면은 **`http://127.0.0.1:5173/dev/components`**에서 엽니다. 주요 메뉴에는 이 화면을 넣지 않았습니다.

`.env` 파일 없이도 Railway API를 호출합니다. `.env.example`에는 `VITE_API_BASE_URL`만 남겼습니다. 서버 주소를 바꾸려면 이 파일을 `.env.local`로 복사해 수정하세요. 기존 `.env.local`이나 배포 환경에 `VITE_DATA_MODE=demo`가 남아 있으면 삭제하고 개발 서버를 재시작하거나 다시 빌드해야 합니다. `VITE_*` 값은 브라우저에 공개되므로 비밀 키를 넣으면 안 됩니다.

**2026-11-21 서버 확인:** 배포 서버의 `/openapi.json`에는 `/health`와 `/health/db`만 있습니다. `/api/v1/home`은 `Not Found`를 돌려줍니다. 계정과 업무 API가 추가되어야 로그인과 데이터 저장을 쓸 수 있습니다. [현재 연결 상태와 백엔드 확인 사항](docs/SERVER_CONNECTION.md)을 참고하세요.

## 빌드와 점검

```bash
npm run lint
npm run build
npm run preview
```

빌드 결과는 `dist/`에 생깁니다. 미리보기 기본 주소는 `http://127.0.0.1:4173`입니다. 배포 설정과 실제 배포는 DevOps 담당 범위입니다. BrowserRouter를 쓰므로 배포 서버에서는 `/work-cards` 같은 직접 접근 주소를 `index.html`로 연결해야 합니다. 하위 경로에 배포한다면 Vite의 `base`와 Router의 `basename`도 함께 설정하세요.

컴포넌트 확인 화면은 기본 프로덕션 빌드에서 열리지 않습니다. 팀 검토용 빌드에 넣으려면 `.env.local`에 `VITE_ENABLE_COMPONENT_PREVIEW=true`를 적고 다시 빌드하세요. 일반 화면의 메뉴는 바뀌지 않습니다.

```bash
npm run test:e2e
```

브라우저 점검은 Playwright로 합니다. Windows에서는 설치된 Microsoft Edge나 Chrome의 기본 경로를 확인해 씁니다. 다른 환경에서는 `npx playwright install chromium`을 먼저 실행하세요. `PLAYWRIGHT_EXECUTABLE_PATH` 환경 변수로 브라우저 실행 파일을 지정할 수도 있습니다. 검사 시 5173 포트를 쓰며 API 모드 화면 검사는 별도 Vite 서버로 5174 포트를 씁니다. 같은 개발 서버가 5173에서 열려 있으면 재사용합니다. 검사 결과와 스크린샷은 `test-results/`에 생기며 Git에 올리지 않습니다.

코드 정렬: `npx prettier --write .`

## 화면 주소와 현재 범위

| 주소              | 현재 내용                              | 다음 작업                 |
| ----------------- | -------------------------------------- | ------------------------- |
| `/`               | 홈 대시보드, 위치 안내, 홈 안의 검색   | 다음 업무 화면 연결       |
| `/work/new`       | 홈 위 업무 등록, 예시 분석과 비교 팝업 | 실제 서버 분석 연결       |
| `/work-cards`     | 개인 업무 카드 페이지 틀               | 4차 카드 저장과 조회      |
| `/history`        | 작업 내역 페이지 틀                    | 4차 작업 결과와 조회      |
| `/dev/components` | 공통 컴포넌트와 상태 확인              | 개발 중 계속 확인         |
| 그 밖의 주소      | 주소 오류 안내와 홈 이동               | 필요한 화면을 차례로 추가 |

홈에서 검색창을 선택하면 추천어가 열리고 입력하면 등록 업무와 개인 업무 카드가 같은 화면의 드롭다운에 표시됩니다. 방향키, Enter, Escape, 검색어 지우기를 쓸 수 있습니다. ‘사용 방법 보기’는 등록된 업무, 이어서 할 일, 개인 업무 카드의 실제 위치를 강조합니다. 작은 화면에서는 안내 상자를 화면 아래에 배치합니다. 후속 업무 버튼은 준비 안내를 열며, 새 업무 등록과 주요 메뉴는 기존 페이지 틀로 이동합니다.

## 예시 데이터와 실제 기능

- `src/data/foundation.js`의 가상 매뉴얼만 예시 응답으로 보여 줍니다. 사용자가 고른 파일에서 추출한 내용이 아닙니다.
- 파일 선택 컴포넌트는 브라우저의 File 객체만 잠시 보관합니다. 파일 바이트를 읽거나 서버에 보내지 않습니다. 자동 업로드, 문서 추출과 AI 분석은 없습니다.
- 파일 형식과 파일당 최대 10MB 제한은 **프런트엔드 데모 기준**입니다. 실제 업로드 제한은 백엔드와 협의해야 합니다. 이 검사는 서버 검증을 대신하지 않습니다.
- 입력값, 체크 상태와 파일 선택은 React 메모리 상태입니다. 새로고침하면 사라집니다. 이번 버전은 localStorage, IndexedDB, 쿠키로 업무 데이터를 저장하지 않습니다. 이후 브라우저 저장을 붙이면 데모용 임시 저장임을 별도로 표시해야 합니다.
- 정상, 오류, 자료 부족 예시는 600ms 뒤 고정 응답으로 바뀝니다. 실제 AI나 서버에 요청하지 않습니다.
- 기본값은 `api`이며 홈에서 Railway의 GET home과 GET jobs를 호출합니다. 실패하면 오류와 다시 시도를 표시하며 예시로 대체하지 않습니다.
- 디자인 확인이 필요한 경우에만 `.env.local`에 `VITE_DATA_MODE=demo`를 직접 적으세요. 이 모드의 데이터와 계정은 예시입니다. 컴포넌트 확인 화면의 가상 매뉴얼 응답도 demo 전용입니다.
- ‘확인 완료’는 사용자가 확인했다는 상태입니다. AI 결과의 정확성을 보증하지 않습니다.
- 업무 기준 자료는 기존 양식과 새 매뉴얼, 작업 자료는 이번에 받은 내역입니다. 개인 업무 카드는 처리 절차, 작업 결과는 이번에 검토하고 수정한 내용입니다.
- 서비스 내부 저장과 외부 시스템 등록은 구분합니다. 외부 재고 시스템 등록, 예약 확정과 주문 전송은 구현 범위에 없습니다.

## 폴더 구조

```text
src/
  App.jsx
  main.jsx
  assets/icons/          피그마에서 내보낸 메뉴 아이콘
  components/
    layout/              공통 레이아웃, 메뉴, 상단 바, AI 패널 틀

  pages/                 페이지 조합과 화면 상태
  data/                  가상 매뉴얼 등 표시용 예시
  services/
    foundationService.js 예시 모드 진입점

    homeService.js       홈의 예시/실제 조회 분기
    api/client.js        JSON, 파일 전송과 원본 응답 공통 함수
  styles/
    tokens.css           디자인 토큰
    global.css           기본 글자와 공통 접근성 스타일
    ui.css               공통 UI
    layout.css           메뉴, 상단 바와 본문 배치
    pages.css            확인용 화면 등 페이지별 배치
tests/                   메뉴, 컴포넌트, 접근성과 API 전송 브라우저 점검
```

Noto Sans KR은 `@fontsource-variable/noto-sans-kr` 패키지로 번들에 포함합니다. 실행 중 외부 폰트 서버를 호출하지 않습니다. 메뉴 아이콘은 Figma 원본에서 내보낸 PNG와 SVG이며 다른 조작 아이콘은 `lucide-react`를 씁니다. 로고는 피그마의 W 표시와 텍스트로 구현했습니다. 화면 전체를 이미지로 넣지 않았습니다. 출처는 `src/assets/README.md`에 적었습니다.

| 바탕        | `#EEF3F9`와 흰색 워크스페이스  | `#F5F7FA`                     |

1440×1080에서 홈의 바깥 여백은 가로 36px, 세로 58px이며 흰색 프레임은 1368×964px, 모서리는 24px입니다. 가운데 열은 792px, 오른쪽 가로 여백은 28px입니다. 화면 폭이 좁아지면 오른쪽 영역을 본문 아래로 옮기고 메뉴는 Drawer로 바꿉니다. 높이를 고정해 내용을 자르지 않고 세로 스크롤을 허용합니다.

`tokens.css`에 홈 배경, 재고 일러스트 배경 `#FFF1E6`, 예약 일러스트 배경 `#EAF6F4`, 홈 제목, 프레임 여백과 그림자 토큰을 추가했습니다. 일러스트 배경 토큰은 홈의 재고·예약 업무 카드에서 씁니다.

## 실제 API 연결 위치

화면에서 직접 fetch를 호출하지 않습니다. `src/services/`의 업무별 서비스와 `src/services/api/client.js`를 통해 요청하세요. `src/services/config.js`에서 기본 API 모드와 서버 주소를 함께 관리합니다. 서버 주소는 `https://gdgoc2026a.up.railway.app`, 경로 접두사는 `/api/v1`입니다. 인증 방식은 아직 확인이 필요합니다. JSON, FormData 업로드, 원본 Response 다운로드와 204 응답 처리를 지원합니다.

트래커의 30개 경로와 요청·성공 응답 예시를 연결 문서에 반영했습니다. 함수명은 **프런트엔드 제안**이며 예시를 최종 스키마로 단정하지 않습니다. 아직 쓰지 않는 빈 함수를 만들지 않았습니다. [API 연결 설명](docs/API_INTEGRATION.md)을 기준으로 다음 차수에서 실제 쓰는 함수부터 추가하세요.

`AppLayout`의 `assistant` prop에 패널을 넘기면 본문 옆의 360px 영역에 배치할 수 있습니다. 화면 폭이 좁아지면 본문 아래로 옮겨집니다. Drawer로 띄울 때는 `AssistantPanel`을 자식으로 넘기세요. 실제 질문 입력과 대화 기록은 3차 작업입니다.

이번 코드는 1차 기반에 수정된 디자인 시스템과 홈 공통 틀을 반영한 상태입니다. 홈 본문과 홈 검색, 온보딩을 추가했고 후속 업무 화면은 이후 차수에 이어서 만듭니다.

현재 실행 환경은 작업 폴더의 `.git` 쓰기를 제한합니다. 소스는 현재 폴더 하나에 두고 Git 기록만 쓰기가 허용된 `C:/workspace/work-bridge-git`에 만들었습니다. 이 환경에서 상태를 보려면 프로젝트 폴더에서 다음 명령을 쓰세요.

```bash
git --git-dir=C:/workspace/work-bridge-git --work-tree=. status
```

다른 컴퓨터에서는 업로드된 작업 브랜치를 복제해 같은 프로젝트를 이어 가세요. 일반 환경에서는 별도 Git 경로 옵션이 필요하지 않습니다.

```bash
git clone --branch "feat/#9" https://github.com/GDGoC-2026TeamA/Frontend.git work-bridge
cd work-bridge
npm ci
npm run dev
```

`node_modules/`, `dist/`, `.env*` 비밀 설정, 검사 산출물은 제외합니다. 소스, 로컬 아이콘, 설정 파일, `package-lock.json`, README와 API 설명을 올립니다. `.env.example`에는 공개 가능한 예시 설정만 넣었습니다. 이전에 전달한 ZIP과 bundle은 최초 로컬 1차 커밋의 보관본입니다.

현재 홈 구현 PR은 `main`을 대상으로 하며 제목에 `[feat/#9]`를 쓰고 본문에 `close #9`와 변경 전후 화면 캡처를 넣습니다. 팀원 한 명 이상이 리뷰하고 승인한 뒤 작성자가 직접 병합하고 작업 브랜치를 삭제합니다. 승인 전에는 이슈를 닫거나 브랜치를 삭제하지 않습니다. 이전 `feat/work-bridge-phase1` 브랜치는 기존 업로드 기록으로 남겨 둡니다.

## 홈 구현 이슈 #9

[구현 이슈 #9](https://github.com/GDGoC-2026TeamA/Frontend/issues/9)의 브랜치는 `feat/#9`입니다. 최신 main에서 만든 뒤 API 수정 PR #8의 기존 커밋을 이어받았습니다. PR #8을 먼저 병합하면 해당 변경은 이 PR의 차이에서 빠집니다.

- 기준 섹션: [1차 / 공통 레이아웃과 홈](https://www.figma.com/design/wX9g6gKuJztvTMWGIhtr9j/?node-id=97-532)
- 홈, 위치 온보딩, 검색 열기, 검색 결과 4개 화면을 같은 홈에서 전환합니다.
- `src/components/home/`은 업무 카드, 오른쪽 내용, 검색과 위치 안내이며 `src/styles/home-dashboard.css`에 화면 스타일을 정리했습니다.
- `src/services/homeService.js`는 예시와 실제 조회를 나눕니다. 실제 모드는 트래커의 GET home과 GET jobs만 씁니다. 요청에 없는 추가 통계나 쓰기 작업을 만들지 않았습니다.
- 서버 응답의 누락 필드를 예시 값으로 채우지 않습니다. 인용문이나 원본을 임의 생성하지 않습니다.
- 2026-11-20 한국 시간에 Railway의 `/api/v1/home`, `/api/v1/jobs`를 GET으로 확인했으며 둘 다 HTTP 404와 `{"detail":"Not Found"}`를 반환했습니다. 이후 서버 구현 상태에 따라 달라질 수 있습니다.

실제 조회를 켜려면 `.env.local`에 아래 값을 적고 개발 서버를 다시 시작하거나 빌드를 다시 하세요. 현재 서버 경로가 404이므로 오류 표시가 예상됩니다.

```dotenv
VITE_DATA_MODE=api
VITE_API_BASE_URL=https://gdgoc2026a.up.railway.app/api/v1
```

브라우저 CORS와 인증 정책은 백엔드에서 확인해야 합니다. 브라우저 테스트의 API 응답은 요청 가로채기로 만든 검사 데이터이며 서버 성공을 뜻하지 않습니다.

## 2차 업무 등록과 자료 비교

[2차 구현과 확인 상태](docs/PHASE2_VALIDATION.md)에 변경 내용과 검사 결과를 적었습니다. 홈의 새 업무 등록 버튼에서 시작합니다. 파일 선택 → 예시 분석 → 비교 → 미확인 항목 수정 → 수정 후 비교까지 같은 팝업에서 전환합니다. 실제 파일은 서버로 전송하거나 분석하지 않습니다. 자료를 다시 올리면 예시 비교 상태를 초기화합니다. 수정 반영 후에도 승인 담당자 질문은 미확인 상태로 남습니다.

2차 작업 이슈는 #11, 브랜치는 `feat/#11`입니다. 로컬 lint, build와 전체 브라우저 검사를 통과했습니다. 비교 화면 캡처와 현재 결과는 docs/PHASE2_VALIDATION.md에 정리했습니다. PR에서 팀 리뷰와 승인 후 병합합니다.

## 로딩, 오류와 빈 상태

[상태 화면 구현과 검사 범위](docs/STATUS_SCREENS.md)를 추가했습니다. 홈의 재고 업무 처리하기에서 `/work/input`으로 들어가 예시 전표의 로딩, 오류, 취소와 재시도를 확인합니다. 실제 파일의 분석은 미연결 안내로 구분합니다. 새 업무 등록의 매뉴얼 누락 영역을 강조하고, 카드와 작업 내역의 빈 화면 및 홈 검색 결과 없음 화면을 최신 디자인에 맞췄습니다.

목록은 기본 api 모드에서 cards/jobs 조회 성공 응답에만 빈 상태를 표시합니다. 명시적으로 선택한 demo 모드는 예시를 보여 줍니다. 오류를 빈 목록으로 바꾸지 않습니다. 초안 생성과 결과 저장은 백엔드 구현이 필요합니다. 기존 차수의 준비 안내보다 이 문단과 연결 문서를 현재 상태의 기준으로 봐 주세요.
